## When to use

- Showing a model's response while it streams.
- Any text that grows over time, such as live transcripts or logs, where new words should arrive gently.

## When not to use

- **Static headlines or marketing copy.** Use [Text Reveal](/docs/components/text-reveal), which staggers a fixed string on mount.
- **Waiting before the first token.** Use [Shimmer Text](/docs/components/shimmer-text) or [Typing Indicator](/docs/components/typing-indicator).

## Usage

```tsx
import { StreamingText } from "@/components/ui/streaming-text"

<StreamingText text={partialText} streaming={isStreaming} />
```

With the AI SDK's `useChat`, pass each message's text and whether it's still streaming. Give every message its own `key` so a new response starts fresh.

```tsx
const { messages, status } = useChat()

{messages.map((message, index) => (
  <StreamingText
    key={message.id}
    text={message.parts.filter((part) => part.type === "text").map((part) => part.text).join("")}
    streaming={status === "streaming" && index === messages.length - 1}
  />
))}
```

## API Reference

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `text` | `string` | | The text received so far. It should only grow; use a new `key` for a new message. |
| `streaming` | `boolean` | `false` | Whether more text is coming. Holds back a half-received word and shows the caret. |
| `effect` | `"blur" \| "fade" \| "rise" \| "typewriter"` | `"blur"` | How new text enters. |
| `by` | `"word" \| "char"` | `"word"`, or `"char"` for typewriter | The unit that animates. |
| `smooth` | `boolean` | `true` | Release text at a steady rate instead of in network bursts. |
| `charsPerSecond` | `number` | `80` | Base reveal rate when smoothing. It speeds up automatically when it falls behind. |
| `caret` | `boolean` | `true` for typewriter | Show a blinking caret while streaming. |

### useSmoothText

The smoothing engine is also exported as a hook for custom renderers.

```tsx
import { useSmoothText } from "@/hooks/use-smooth-text"

const { text, pending } = useSmoothText(partialText, { charsPerSecond: 80, catchUp: 3 })
```

## Accessibility

The container sets `aria-busy` while text is arriving. Words are real text in the DOM, so screen readers and copy and paste work normally. If you announce responses with a live region, announce the finished message rather than every word.

## Motion

Each new word enters once with the **gentle** spring, without overshoot, and never animates again. Text already on screen when the component mounts, like chat history, appears instantly. Smoothing releases characters at a base rate plus a share of the backlog, so it never lags far behind the network. With reduced motion, smoothing and effects are off and text appears as it arrives.

## Notes for AI

- Pass the accumulated text, not the latest chunk.
- Key each message by its id. Reusing one component for different messages shows the new text instantly.
- Use `effect="typewriter"` for code-like or terminal output, and `blur` for prose.
