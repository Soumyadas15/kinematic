## When to use

- Uploads, imports or multi-step tasks where you know the percentage.
- Showing usage against a limit, like storage.

## When not to use

- **Unknown duration.** Use a spinner or a [Skeleton](/docs/components/skeleton).
- **Picking a value.** Use a [Slider](/docs/components/slider).

## Installation

<AddCommand slug="progress" />

## Usage

```tsx
import { Progress } from "@/components/ui/progress"

<Progress value={42} aria-label="Upload progress" />
<Progress value={7.2} max={10} aria-label="Storage used" />
```

## API Reference

### Progress

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `value` | `number \| null` | | Current value. `null` means indeterminate. |
| `max` | `number` | `100` | The value that counts as complete. |
| `getValueLabel` | `(value: number, max: number) => string` | | Custom text for `aria-valuetext`. |

## Accessibility

Built on Radix Progress. Renders `role="progressbar"` with `aria-valuemin`, `aria-valuemax`, `aria-valuenow` and `aria-valuetext`. Give it an `aria-label` or `aria-labelledby` so it's clear what is progressing.

## Motion

The fill springs to each new value with the **smooth** spring, so frequent small updates read as one continuous movement and new values interrupt cleanly. It doesn't animate on first render. Instant with reduced motion.

## Notes for AI

- Pass `max` instead of converting to a percentage yourself.
- Always label it. A bare progress bar means nothing to a screen reader.
