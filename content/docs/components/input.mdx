## When to use

- Short, single-line values such as names, emails, URLs and search queries.
- Any native input type: `email`, `password`, `number`, `search`, `file`.

## When not to use

- **Multi-line text.** Use a [Textarea](/docs/components/textarea).
- **Choosing from a fixed set.** Use a [Select](/docs/components/select) or a [Radio Group](/docs/components/radio-group).
- **One-time codes.** Use [Input OTP](/docs/components/input-otp).

## API Reference

### Input

Accepts every native `<input>` prop.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `type` | `string` | `"text"` | Native input type. |
| `aria-invalid` | `boolean` | | Shows the destructive border and ring. |
| `disabled` | `boolean` | `false` | Dims the field and blocks interaction. |

## Accessibility

Renders a native `<input>`, so browser behaviour, autofill and form submission work as usual. Give it a visible [Label](/docs/components/label). Set `aria-invalid` when validation fails and link the error text with `aria-describedby`. The focus ring only shows for keyboard focus (`:focus-visible`).

## Motion

CSS transitions on border color and box shadow. The border tints on hover, then the ring grows out to 3px on focus. No Motion library needed here, because a field should never move under the cursor. Respect for reduced motion comes from the short, color-only transition.

## Notes for AI

- Use `aria-invalid`, not a custom red class, for error state. The styles already key off it.
- For an icon inside the field, wrap it in a `relative` div, position the icon absolutely and add left padding to the input.
- Keep `text-base` on mobile. It stops iOS from zooming on focus. The component switches to `text-sm` from `md` up.
