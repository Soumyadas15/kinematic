## When to use

- Persistent, page-level information like a failed payment or scheduled maintenance.
- Form-level errors that need to stay visible.

## When not to use

- **Temporary feedback after an action.** Use a toast with [Sonner](/docs/components/sonner).
- **Confirming a destructive action.** Use an [Alert Dialog](/docs/components/alert-dialog).

## Usage

```tsx
import { Alert, AlertDescription, AlertTitle } from "@/components/ui/alert"

<Alert variant="destructive">
  <CircleAlert />
  <AlertTitle>Payment failed</AlertTitle>
  <AlertDescription>Update your billing details.</AlertDescription>
</Alert>
```

## API Reference

### Alert

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `variant` | `"default" \| "destructive"` | `"default"` | Visual style. |

Also exported: `AlertTitle` and `AlertDescription`.

## Accessibility

The alert has `role="alert"`, so screen readers announce it when it's inserted. For content present on page load that isn't urgent, pass `role="status"` or `role={undefined}` to avoid an interruption.

## Motion

None. Alerts are static. If one appears in response to an action, animate the container that mounts it.

## Notes for AI

- Put the icon as the first direct child. The grid only reserves an icon column when an `svg` is a direct child.
- Use multiple `<p>` elements in `AlertDescription` for paragraphs. They get spacing automatically.
