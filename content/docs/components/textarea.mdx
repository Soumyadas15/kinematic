## When to use

- Free-form text: comments, feedback, descriptions, messages.
- Fields where the length is unknown and should grow as people type.

## When not to use

- **Short, single values.** Use an [Input](/docs/components/input).
- **Rich text editing.** Use a dedicated editor.

## API Reference

### Textarea

Accepts every native `<textarea>` prop.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `rows` | `number` | | Native rows. The field still grows past it with content. |
| `aria-invalid` | `boolean` | | Shows the destructive border and ring. |
| `disabled` | `boolean` | `false` | Dims the field and blocks interaction. |

## Accessibility

Renders a native `<textarea>`. Pair it with a [Label](/docs/components/label) and link helper or error text with `aria-describedby`. The focus ring only shows for keyboard focus.

## Motion

CSS transitions on border color and box shadow, like Input. Height follows content through `field-sizing: content`, so growth is native and never lags the caret. Browsers without `field-sizing` fall back to a fixed, resizable field.

## Notes for AI

- Cap growth with `max-h-*` and the field will scroll past it. Do not add JavaScript auto-resize on top.
- Set the minimum height with `min-h-*`, not `rows`, since `field-sizing-content` ignores `rows` when content is shorter.
